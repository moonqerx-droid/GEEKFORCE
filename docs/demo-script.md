# Сценарий демо-видео (3–4 минуты)

Каждая фраза ниже проверена на стенде 28.09.2026: ответы помощника совпадают с приведёнными.
Печатайте фразы как есть — опечатки и сленг там намеренно.

## Перед записью

1. `docker compose up -d --build`, затем `docker compose exec api python -m app.seed_demo`.
2. Ollama запущена, модели на месте: `ollama list` показывает `bge-m3` (смысловое понимание).
   В `.env`: `AI_PROVIDER=ollama`. Без Ollama всё работает, но сленг понимается хуже.
3. `npm run dev` в `apps/web`, открыть http://localhost:5174 — на странице входа есть «Быстрый вход».
4. Подтвердите демо-сбой VPN, чтобы сотрудники видели плашку: войдите специалистом
   (Анна), в «Массовые проблемы» откройте VPN → «Подтвердить сбой». Или запишите это как отдельную сцену (сцена 6).
5. Окно браузера 1440×900, масштаб 100 %.

## Сцены

### 1. Вход в один клик — 10 с
Страница входа → «Быстрый вход» → **Сотрудник**.
> «Три роли: сотрудник, специалист поддержки, руководитель. Заходим как сотрудник.»

### 2. Пример из кейса — 40 с
Напишите: **У меня опять всё сломалось. С телефона CRM открывается, с ноутбука нет. Через 20 минут встреча!**

Помощник: срочность «высокая» (причина — встреча), сценарий «Не удаётся войти в рабочую систему»,
один вопрос: «Что появляется на ноутбуке, когда пытаетесь войти?».
Справа «Что я понял» уже заполнена: устройство — ноутбук, на телефоне работает.
Ответьте: **пишет что-то про сертификат** → первый шаг. Нажмите «Не помогло» → следующий шаг.
> «Помощник не устраивает анкету: он уже понял из текста устройство и срочность и спрашивает только то, от чего зависит следующий шаг.»

### 3. Сотрудник пишет как есть — 30 с
Новое обращение: **комп жутко тупит**
→ «Медленно работает компьютер», вопрос «У коллег это тоже работает медленно?» с кнопками Да / Нет / Не знаю.
> «Ни одного ключевого слова — помощник понимает смысл. Опечатки тоже: „ранботало“, „принтр“.»

Новое обращение: **Ничего не работает, помогите**
→ «Пока не ясно, что случилось. На что это похоже?» и кнопки: Вход или пароль, Почта, VPN, Интернет или Wi-Fi, Всё медленно работает, Нет доступа…, Другое.
Нажмите **Почта** → «Где вы работаете с почтой — в программе Outlook или в браузере?» с кнопками.
> «Если непонятно — один вопрос с вариантами, а не три одинаковых вопроса на всё.»

### 4. Правила компании — по документу — 25 с
Новое обращение: **Какие требования к паролю?**
→ карточка «Ответ по документам компании»: «Пароль… меняется раз в 90 дней. Новый пароль — не короче 10 символов…»,
раскрывающийся «Источник: «Правила паролей»». Нажмите **Да, это ответ** → обращение закрыто, оценка.
> «О правилах компании помощник говорит только по загруженным документам и показывает цитату. Общий совет всегда подписан „не правило компании“.»

### 5. Передача специалисту — 40 с
В обращении из сцены 2 нажмите «Позвать специалиста» (или «Не помогло» до конца шагов).
Внизу: «Передали специалисту… Срочные обращения берут в работу в течение часа» (срок зависит от срочности).
Переключитесь на **Специалиста** (быстрый вход, новая вкладка): обращение наверху очереди, справа
«Карточка обращения» — исходные слова, вопросы и ответы, выполненные шаги, причина передачи.
Напишите ответ → вернитесь к сотруднику: ответ специалиста в том же чате; если вкладка была в фоне,
в её заголовке «(1) Ответ специалиста».
> «Специалист ничего не переспрашивает: всё уже в карточке.»

### 6. Радар инцидентов — 30 с
Специалист: блок «Массовые проблемы» → VPN, «затронуто 5». Внутри — кто и что написал. «Подтвердить сбой».
Сотрудник → «Новое обращение»: над «Что случилось?» плашка «VPN: известный сбой, уже чиним» и кнопка
**У меня то же самое** — одно нажатие, и сотрудник в списке затронутых.
> «Когда ломается общий сервис, никого не гоняют по диагностике, а специалист отвечает всем одним сообщением.»

### 7. Руководитель — 20 с
Быстрый вход → **Руководитель поддержки**: доля решённых без специалиста, время ответа, оценки,
темы; «Пользователи» — выдать доступ специалисту; «База знаний» — загрузить документ.

### 8. Качество измеряется — 15 с
В терминале (локально, в окружении с `pip install -r apps/api/requirements.txt`):
`cd apps/api && PYTHONPATH=../../services/ai python -m app.eval_dialogues --semantic`
> «153 эталонных диалога, как пишут живые люди. Поведение в диалоге — 100 %, распознавание на
> свежих фразах, которых система не видела, — 90 %. Всё локально и бесплатно, данные не уходят из компании.»

## Если что-то пошло не так

- Нет плашки сбоя у сотрудника — сбой не подтверждён специалистом (сцена 6).
- «комп жутко тупит» даёт «На что это похоже?» — не запущена Ollama или нет `bge-m3`; перезапустите API
  после `ollama pull bge-m3`, подождите ~20 с, пока соберётся индекс.
- Нужны чистые данные: `docker compose down -v` и заново шаги 1 и 4.
