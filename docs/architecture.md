# Архитектура GEEKFORCE HelpFlow

## Общая схема

```text
┌──────────────┐        ┌──────────────┐
│  apps/web    │        │ apps/operator│
│  (сотрудник) │        │ (специалист) │
└──────┬───────┘        └──────┬───────┘
       │  HTTP/JSON            │
       └───────────┬───────────┘
                   ▼
           ┌───────────────┐
           │    apps/api   │  FastAPI
           │  маршруты +   │  SQLite + SQLAlchemy
           │  стейт-машина │
           └───────┬───────┘
                   │
       ┌───────────┼────────────┐
       ▼           ▼            ▼
┌────────────┐ ┌─────────┐ ┌──────────────┐
│ services/ai│ │knowledge│ │services/      │
│ AIService  │ │-base    │ │incidents     │
│ protocol   │ │playbooks│ │Incident Radar│
└────────────┘ └─────────┘ └──────────────┘
```

## Ключевое решение

AI-поведение спрятано за протоколом `AIService`. Для MVP используется детерминированная mock-реализация (`AI_PROVIDER=mock`), которая позже заменяется на реальный LLM без изменений в маршрутах и фронтенде.

**Переходы диалога контролирует backend, не LLM.** Свободный вывод модели никогда не управляет состоянием напрямую.

## Слои backend

- `app/api/routes/` — тонкие маршруты, без бизнес-логики
- `app/services/dialogue.py` — стейт-машина диалога
- `app/services/ai.py` — `AIService` protocol + `MockAIService`
- `app/repositories/` — доступ к данным
- `app/models/` — SQLAlchemy-модели
- `app/schemas/` — Pydantic-контракты

## Состояния диалога

```
NEW
→ ANALYZING
→ CLARIFYING
→ TROUBLESHOOTING
→ VERIFYING
→ RESOLVED | ESCALATED
```

Разрешённые переходы:

```
NEW -> ANALYZING -> CLARIFYING
CLARIFYING -> TROUBLESHOOTING
TROUBLESHOOTING -> TROUBLESHOOTING | VERIFYING | ESCALATED
VERIFYING -> RESOLVED | TROUBLESHOOTING | ESCALATED
```

Недопустимое событие → доменное исключение `DialogueConflict` → HTTP 409.

## Incident Radar

Сравнивает новое обращение с активными. При достаточном сходстве создаёт кластер и показывает оператору возможный массовый инцидент. Порог задаётся `INCIDENT_SIMILARITY_THRESHOLD`.

## Хранилище

SQLite на время хакатона, доступ через SQLAlchemy 2. Позже — PostgreSQL без изменения кода доступа (только `DATABASE_URL`).

## Расширение

Точки расширения, оставленные явно:

- замена `MockAIService` на реальный LLM-провайдер;
- переход на PostgreSQL;
- семантическая кластеризация Incident Radar через embeddings;
- аутентификация и управление организациями.

## Коды ошибок

| Код ↕▾ | Когда ↕▾ |
|---|---|
| −422 | Пустое или whitespace-only сообщение; не создаёт запись |
| 404 | Неизвестный ID обращения; не 500 |
| 409 | Результат шага отправлен в неверном состоянии; состояние не меняется |
| 409 | Недопустимый переход стейт-машины (`DialogueConflict`) |
⚙

## Идемпотентность

- Повторный `POST /step-result` сохраняет историю, не перезаписывает.
- Эскалация идемпотентна после достижения `ESCALATED`.

# Сценарий защиты (4 минуты)

## 0:00–0:25 — проблема

> Сотрудники не знают технических терминов, пишут эмоционально, а поддержка затем заново собирает контекст.

## 0:25–1:40 — основной сценарий

Демонстрационное сообщение:

> Не могу войти в CRM с ноутбука, но с телефона работает. Через 20 минут встреча.

Показать:

- сложное срочное обращение;
- извлечённые симптомы (ноутбук / телефон);
- срочность `high` и её причину («встреча через 20 минут»);
- один релевантный вопрос;
- последовательные шаги;
- проверку результата.

## 1:40–2:30 — эскалация

Показать нерешённую проблему и открыть операторскую панель. Специалист должен видеть:

- исходное обращение;
- уточняющие вопросы и ответы;
- предполагаемую проблему;
- уровень и причину срочности;
- выполненные действия и их результат;
- AI-резюме.

## 2:30–3:20 — Incident Radar

Показать:

- обнаружение похожих обращений;
- создание общего инцидента;
- уведомление связанных пользователей.

## 3:20–4:00 — эффект

Метрики, которые система умеет измерять на тестовых сценариях:

- количество вопросов до решения;
- доля самостоятельно решённых обращений;
- время подготовки обращения для специалиста.

> Нельзя выдавать демонстрационные значения за результаты реального внедрения.

## Резервный план

- Локальный запуск без интернета.
- Mock AI (`AI_PROVIDER=mock`) без внешнего ключа.
- Записанное видео на случай отказа инфраструктуры.
