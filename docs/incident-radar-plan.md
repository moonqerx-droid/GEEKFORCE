# План Incident Radar (services/incidents)

Владелец: Участник 4.

## Назначение

Объединяет похожие обращения в возможный массовый инцидент, чтобы:

- не заставлять каждого пользователя проходить одну и ту же диагностику;
- показать оператору возможный массовый сбой;
- позволить оператору отправить обновление всем связанным пользователям.

## Как работает

1. Новое обращение сравнивается с активными.
2. При сходстве выше порога (`INCIDENT_SIMILARITY_THRESHOLD`) создаётся или расширяется кластер.
3. Подходящие обращения связываются (`incident_id`).
4. Пользователю сообщается, что проблема может быть массовой.
5. Оператор видит инцидент и может разослать обновление.

## Метод сравнения

- MVP: простой similarity search (токенизация + косинусное сходство либо difflib).
- Позже: embeddings.

## Критерий готовности

Во время демонстрации четвёртое обращение попадает в существующий кластер, меняет интерфейс пользователя, появляется в операторской панели и получает общее обновление статуса.
