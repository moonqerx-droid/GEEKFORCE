# Операторы, админ-панель и редизайн «Тёплый помощник»

Дата: 27 сентября 2026. Ветка: `codex/auth-integrated`.

## Зачем продукт

HelpFlow нужен компании, где внутренняя поддержка перегружена однотипными обращениями.

- **Сотрудник** в стрессе («через 20 минут встреча») быстро и без раздражения возвращает себе рабочую систему, не зная терминов и категорий.
- **Оператор** получает не переписку, а готовое обращение: что понял помощник, ответы, выполненные шаги, причина передачи. Отвечает в том же чате, сотрудник ничего не пересказывает.
- **Руководитель поддержки (админ)** видит, сколько обращений закрыто без людей, где помощник не справляется и как нагружена команда.

Путь обращения: описал своими словами → помощник понял суть, сервис и срочность → 1–3 нужных вопроса → шаги по одному → решено и оценено, либо оператор подключается в тот же чат → решено и оценено.

## Роли

`employee`, `operator`, `admin`. Админ имеет все права оператора плюс управление командой и метрики.

- Сотрудники регистрируются сами с подтверждением почты.
- Операторов приглашает только админ. По ссылке-приглашению оператор задаёт имя и пароль; почта считается подтверждённой приглашением.
- Первый админ создаётся при старте API из `ADMIN_EMAIL` / `ADMIN_PASSWORD`, если такого пользователя ещё нет.

## Модель данных (миграция `20260927_0006`)

`conversations`:
- `assignee_id` — FK на `users`, оператор в работе;
- `escalated_at`, `assigned_at`, `first_operator_reply_at`, `resolved_at` — метки времени;
- `resolved_by` — `assistant` | `operator`;
- `rating` (1–5), `rating_comment`.

`messages`: `author_id` (FK на `users`, nullable); новая роль `operator`.

`operator_invites`: `first_name`, `last_name`, `invited_by_id`.

Статусы: добавлен `IN_PROGRESS` (оператор взял обращение). Путь после передачи: `ESCALATED` → `IN_PROGRESS` → `RESOLVED`.

## API

Сотрудник:
- существующие `/api/conversations/*` без изменений контракта;
- в `ESCALATED` / `IN_PROGRESS` сообщения сотрудника сохраняются без ответа помощника — их читает оператор;
- `POST /api/conversations/{id}/rating` `{rating, comment?}` — только владелец, только `RESOLVED`.

Оператор (и админ):
- `GET /api/operator/tickets?scope=queue|mine|resolved` — очередь; по умолчанию `ESCALATED` + `IN_PROGRESS`, срочные первыми;
- `GET /api/operator/tickets/{id}`;
- `POST /api/operator/tickets/{id}/assign` — взять себе; чужое обращение → 409;
- `POST /api/operator/tickets/{id}/messages` `{content}` — ответ; первый ответ фиксирует `first_operator_reply_at`; неназначенное обращение назначается автоматически;
- `POST /api/operator/tickets/{id}/resolve` `{summary}` — закрыть с итогом, `resolved_by=operator`.

Админ:
- `GET /api/admin/operators` — операторы и ожидающие приглашения;
- `POST /api/admin/operators/invite` `{email, first_name, last_name}` → `{invite_url, expires_at, email_sent}`;
- `PATCH /api/admin/operators/{id}` `{is_active}`;
- `GET /api/admin/metrics?days=7|30` — сводка (см. ниже).

Живой чат: обе стороны опрашивают `GET` обращения раз в 2–3 секунды.

## Метрики

За период: всего обращений; решено помощником / оператором / открыто; доля решённых без оператора; медиана времени до решения; медиана времени до первого ответа оператора; средняя оценка и число оценок; обращения по дням (помощник / оператор / открыто); топ сценариев по количеству с долей эскалаций; распределение срочности; нагрузка по операторам (в работе, закрыто, медиана времени до решения).

## Демо-данные

`python -m app.seed_demo` — идемпотентно создаёт админа, двух операторов, пятерых сотрудников с подтверждённой почтой и ~60 обращений за 14 дней (≈65% решены помощником, остальные у операторов, часть оценена). Пароли демо-аккаунтов печатаются в консоль и описаны в README.

## Дизайн «Тёплый помощник»

Тёплый светлый фон `#fbf7f2`, белые карточки, коралловый акцент `#e8572a`, тёмно-коричневый текст `#2a211b`, мягкие скругления, аватар помощника, человеческий короткий тон. Цвет несёт смысл: срочность, статус, действие. Один стиль на все три роли.

- Сотрудник: «Что случилось?» с примерами → чат, где помощник показывает, что понял (сервис, срочность с причиной), вопросы, карточка шага с тремя исходами и прогрессом, подключение оператора в той же ленте, оценка.
- Оператор: трёхпанельное рабочее место — очередь, чат, карточка контекста от помощника.
- Админ: дашборд метрик, команда и приглашения.

## Вне объёма отбора

Радар инцидентов (контр-фича к финалу), шаблоны ответов, вебсокеты, фильтры всех обращений в админке, переключение режима ИИ из интерфейса.
