# Автоматическая проверка сценариев кейса

Скрипт `scripts/check-case.py` проверяет первое действие помощника через публичный HTTP API.
Он входит демо-сотрудником, создаёт отдельное обращение для каждого сценария и печатает
статус, тип ответа, первое сообщение помощника и задержку. При несовпадении ожиданий
процесс завершается с кодом `1`, при ошибке входа — с кодом `2`.

## Запуск

Из корня репозитория:

```bash
python scripts/check-case.py --base-url http://127.0.0.1:8000
```

Значения по умолчанию соответствуют демо-стенду:

- сотрудник: `ivan@helpflow.demo`;
- администратор для чтения списка документов: `admin@helpflow.demo`;
- пароль: `DemoPass123`.

Параметры можно переопределить без изменения файла:

```bash
python scripts/check-case.py \
  --base-url http://127.0.0.1:8010 \
  --email ivan@helpflow.demo \
  --admin-email admin@helpflow.demo \
  --password DemoPass123
```

Если администратор загрузил хотя бы один документ со статусом `ready`, скрипт читает его
название и первый фрагмент, формирует дополнительный вопрос сотрудника и требует
`answer_kind=document` вместе с непустой цитатой `document:*`. Административная сессия
используется только для `GET`: скрипт ничего не загружает, не архивирует и не меняет.
Если документа нет, эта проверка явно помечается `SKIP`.

Для заранее известного документа вопрос можно задать явно:

```bash
python scripts/check-case.py \
  --base-url http://127.0.0.1:8010 \
  --document-question "Как подключиться к VPN при ошибке 809?"
```

Скрипт создаёт только обращения демо-сотрудника. Пользователей, документы, инциденты и
настройки он не изменяет.
